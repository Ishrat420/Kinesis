# Core Principles

These principles guide every design and engineering decision made in Kinesis.

---

# 1. Everything is Connected

No piece of information should exist in isolation.

Objects can relate to multiple modules, goals, people, documents, and reminders.

Connections create context.

---

# 2. Objects Own Data

Objects are the foundation of Kinesis.

Examples:

- Person
- Vehicle
- Passport
- Goal
- Property
- Subscription

Objects exist once.

Everything else references them.

---

# 3. Modules Organize

Modules provide structure.

Modules do not own information.

An object may appear in multiple modules without duplication.

Examples:

- Passport

Appears in:

- Documents
- Travel
- Goals
- Search
- Timeline

---

# 4. Search is Universal

Search should find everything.

Users should never need to remember where something was stored.

---

# 5. AI Assists

Artificial Intelligence should:

- Extract information
- Connect related information
- Suggest actions
- Answer questions

AI is passive. 

The user always remains in control.

---

# 6. Enter Information Once

Users should never manually enter the same information multiple times.

Once information exists, it should be reusable everywhere.

---

# 7. Relationships Matter

Relationships are first-class citizens.

Knowing that a passport exists is useful.

Knowing:

- who owns it
- what trip depends on it
- when it expires

is significantly more valuable.

---

# 8. Integrate Before Replacing

Dedicated applications should continue doing what they do best.

Kinesis connects them rather than replacing them.

---

# 9. Build for Longevity

Features should remain useful for many years.

Avoid trends and unnecessary complexity.

Choose clarity over cleverness.

---

# 10. Simplicity Wins

Every new feature increases complexity.

Only add functionality that creates meaningful value.

When in doubt, simplify.
